## Divergence Notes

<!-- Record any deviation from the approved plan (and why) as implementation proceeds. -->

- **`isParentMode` rule (2.1)**: aligned to `intake.md` ("launched against a directory whose own `openspec/` is absent") rather than `research-plan.md` step-1's stricter "AND ≥1 child has one". Reason: the stricter rule makes checkpoint 2.6's "parent mode with zero `openspec/` children" empty-state unreachable. So `isParentMode = launchDir lacks its own openspec/`; `defaultProjectPath` is `null` when no child qualifies (drives 2.6).
- **`getRealPath` not reused (2.1)**: it is module-private (not exported from core). Discovery routes through `resolve()` (which `reactiveStat`/`reactiveReadDir` already apply internally); separator-agnostic containment stays the job of `isPathInsideOrEqual` at the switch guard (2.3).
- **Discovery uses plain `node:fs`, NOT reactive-fs (2.1 — supersedes the earlier reactive-fs plan)**: the launched server's `@parcel/watcher` is scoped to its *own* (child) project dir, so it can never observe parent/sibling changes. A reactive-fs `stateCache` entry would therefore pin a permanently-stale project list (new siblings never appear, even on reload). `discoverProjectRoots` now calls `readdir`/`stat` from `node:fs/promises`, read fresh on every invocation, so each `overview` query reflects the current sibling set.
- **`projects.subscribe` removed (2.3 — supersedes plan)**: the reactive subscription in the plan would emit once from the child's watcher and never update (a foot-gun implying live sibling tracking that cannot exist — see the reactive-fs note). `projectsRouter` is now `{ overview: query, switchProject: mutation }` only.
- **Web dropdown reads `projects.overview` (2.5 — supersedes `projects.subscribe`)**: the switcher uses a `useQuery(['projects','overview'])` with `refetchOnMount: 'always'` + `refetchOnWindowFocus`, so a client mount/reload (and the full reload that A1's handoff performs) picks up the current sibling set. No subscription/WebSocket dependency. The query is factored into a shared `useProjectsOverview` hook (`packages/web/src/lib/use-projects-overview.ts`) bound to the app's singleton `queryClient`, so both the switcher and the empty-state gate work without a surrounding `QueryClientProvider` (they mount in the layout shell and in isolated tests).
- **2.3 guard tests were backfilled during 3.2**: checkpoint 2.3 had been marked done but `packages/server/src/router.test.ts` held no `projectsRouter` coverage. Added a `describe('projectsRouter (multi-project switcher)')` block (6 cases) driving the real router through `appRouter.createCaller` over temp-dir fixtures: parent-mode `overview` (children + `hasOpenspec` flags), single-project `overview` (self-referential entry), `switchProject` accept (openspec sibling → `ensureWorktreeServer`), reject non-openspec sibling, reject outside-parent path (exercises the `isPathInsideOrEqual` guard specifically), reject in single-project mode. `router.test.ts` now 49/49.
- **3.2 baseline characterization**: `pnpm tc` and `oxlint` are fully green. Feature-package builds (core → server → web) are green; the full `pnpm build` is blocked only by `ct2-engine` (ctranslate2) needing a Rust/cargo toolchain absent from this env — unrelated to the feature. Every remaining test red is pre-existing Windows/env baseline, reproducible on files the feature never touches: web `44×` = `localStorage.clear is not a function` (jsdom stub); core = Windows `\`-vs-`/` path separators (`reports\summary.md`), lockfile-vs-fallback package-manager detection, a POSIX-only reactive-fs test util, plus two FOREIGN in-flight files (`config.test.ts`, `opsx-kernel.test.ts`); server `10×` = git default-branch naming (`'main'` vs `'origin/main'`) + `EBUSY … rmdir` temp-dir teardown locks on Windows. The feature's own suites (`project-discovery`, `path-inside`, `project-switcher`, `project-empty-gate`, `projectsRouter`) are all green.
- **Empty-state is a full-screen gate, not an inline banner (2.6)**: `ProjectEmptyGate` (`packages/web/src/components/project-empty-gate.tsx`) mirrors `CliHealthGate` — mounted in `root-layout.tsx` right after `CliHealthGate`, it renders a `fixed inset-0` overlay only when `overview.parentMode && no child has openspec/`. It names `parentRoot` and lists the skipped folders, then hides itself the moment any `openspec/`-bearing project exists. This is cleaner than special-casing the generic empty route and keeps the "no projects" message consistent across every route.
